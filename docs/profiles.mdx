# Profiles

A **profile** is a saved selection: one alternative per node, plus any
parameter overrides. It is how you bring a system up the same way every time,
in the TUI or headless with `sheppy up`.

## Where they live

One YAML file per profile, in a `profiles/` directory next to the manifest.
The filename is the profile's name: `profiles/mock.yaml` is the profile `mock`.
A name is letters, digits, `_`, and `-` (`[A-Za-z0-9_-]`, no slashes or
dots); a file named anything else is not a profile and won't load.

```
my_robot/
├── sheppy-manifest.yaml
└── profiles/
    ├── mock.yaml
    └── real.yaml
```

Profiles are plain text; commit them alongside the manifest.

## The format

```yaml
# profiles/mock.yaml
selections:              # node name -> alternative id
  camera: mock_camera
  perception: gpu_detector
overrides:               # optional: node name -> param -> value
  camera:
    frame_rate: 15
```

- A node missing from `selections` has nothing selected. If it's running,
  `sheppy up` stops it.
- An override only applies to a param the selected alternative lists under
  `params` in the manifest. Any other key is dropped with a warning, and so is
  an override for a node that isn't selected.
- A selection that names a node or alternative the manifest doesn't have is
  dropped with a warning. The rest of the profile still loads.

## Making one

- **In the TUI:** select alternatives, edit params with `p`, then press `s` and
  type a name. `l` lists profiles to load; `d` in that list deletes one.
- **By hand:** write the file in the format above.
- **From what's running:** `!` in the TUI copies what `sheppyd` is running into
  the selection. Press `s` to save it.

In the TUI header, a `*` after the profile name means the selection has
changed since you last loaded or saved.

## Bringing a profile up

```bash
sheppy up mock                                       # uses ./sheppy-manifest.yaml
sheppy up mock --manifest /home/me/robot/sheppy-manifest.yaml
```

`sheppy up` compares the profile with what's running. It:

- starts selected nodes that aren't running;
- restarts nodes that are running a different alternative, command, or params;
- **stops nodes in the manifest that the profile doesn't select**;
- leaves nodes from other manifests alone;
- leaves a selected node as it is when its launcher fails to resolve, and
  reports the failure.
- leaves a node as it is, and reports why, when its selected alternative has
  manifest errors.

It prints that plan first, sends every start at once (there's no ordering
between nodes), waits for them to settle (bounded by the daemon's grace
periods, 22 seconds with the defaults), and prints each node's final state. It exits 1 if a selected node isn't running at the end
(it crashed, or `sheppyd` couldn't start it), a launcher failed to resolve,
a selected alternative has manifest errors,
the manifest or profile didn't load, or the nodes didn't settle in time.
Running it again prints
`already converged`. See the [CLI reference](../cli#sheppy-up-profile---manifest-path)
for the details.

In the TUI, `Shift+L` does the same for the current selection, after showing
the plan and asking you to confirm.

## Profiles in the TUI

The TUI always opens with no profile loaded (see [TUI](../tui)). Loading one
with `l` changes the selection only. Nothing starts until you press `space`
or `Shift+L`.
