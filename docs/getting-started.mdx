# Getting started

## Install

One line — installs [uv](https://docs.astral.sh/uv/) if you don't have it,
then puts `sheppy` and `sheppyd` on your `PATH` (`~/.local/bin`) in an
isolated environment:

```bash
curl -LsSf https://rammp-org.github.io/sheppy/install.sh | sh
```

Re-run the same line to upgrade. Pin a branch, tag, or commit with
`SHEPPY_REF=<ref>`; uninstall with `uv tool uninstall sheppy`.

<Callout type="info">
Already have uv? `uv tool install git+https://github.com/rammp-org/sheppy@main`
does the same thing.
</Callout>

## Run the demo — no ROS required

The repo ships `examples/local-demo.yaml`, a manifest that launches plain
Python processes instead of ROS nodes, so you can watch sheppy run something
on any machine without ROS installed:

```bash
git clone https://github.com/rammp-org/sheppy.git
cd sheppy
sheppy examples/local-demo.yaml
```

The manifest declares two nodes: `clock` (an alternative called `ticker`
that prints the time every second) and `worker` (`steady`, which just sleeps,
and `flaky`, which exits with status 1 after three seconds). That's enough to
walk through everything below.

## The 90-second walkthrough

<Steps>
### Select `clock` → `ticker`

Both rows start with a `?`: `sheppyd` isn't running yet, so their state is
unknown. `Enter` opens `clock`'s alternatives, `Enter` again selects `ticker`
(its only one), `Esc` returns focus to the node list. The row's ALTERNATIVE
column now reads `ticker`, and the header shows `profile <none>*` — an
unsaved selection.

### Launch it — `space`

Within a couple of seconds the row's status glyph turns `●` (green) and the
footer reads `sheppyd ● 1/2 running` — `sheppyd` auto-started on this first
launch.

### Watch it run

Press `3` for the PROCESS tab: `state`, `pid`, a live `uptime`, and a "last
output" tail printing `clock`'s heartbeat, one new line per second.

### Crash it on purpose

Move to `worker` (`↓`) and select `flaky` (`Enter`, `↓`, `Enter`, `Esc`). The
row shows `Δ` straight away: `flaky` is selected, but nothing is running for
`worker`. Press `space` to launch it. It runs for about three seconds, then
its glyph turns `✕` (crashed), and the `Δ` stays. The PROCESS tab says why:

```
state       ✕ crashed
drift       Δ flaky selected, not running
pid         3948421
exit code   1
```

See [desired vs actual](../concepts#desired-vs-actual), and
[the TUI](../tui#the-screen) for what the whole screen looks like now.

### Read its logs

From a second terminal:

```
$ sheppy status
clock                running    ticker         pid=3948253 up 22s
worker               crashed    flaky          pid=3948421 exit=1
```

`flaky` exits without printing anything, so `sheppy logs worker` comes back
empty; the exit code in `sheppy status` is what tells you it failed:

```
$ sheppy logs worker
(no output)
```

### Save the selection as a profile — `s`

Type a name (e.g. `demo`), `Enter`. The header now reads `◆ profile demo`,
and `profiles/demo.yaml` appears next to the manifest:

```yaml
selections:
  clock: ticker
  worker: flaky
```

Because the demo manifest is in `examples/`, that `profiles/` directory is
created inside your clone; git ignores it.

### Tear down

Quit the TUI (`q`), then from a shell:

```
$ sheppy down
stopped clock
stopped worker
sheppyd stopped
```
</Steps>

<Callout type="info">
`sheppyd` is the background daemon that runs these processes. They keep
running when you quit the TUI, and the TUI shows them again when you reopen
it. For
architecture, node states, and troubleshooting, see the
[sheppyd guide](../guides/sheppyd).
</Callout>

## Now describe your own system

`local-demo.yaml` is only a demo. See [Manifest](../manifest) to write one for
your own nodes, alternatives, and machines, then read
[ROS integration](../ros-integration) before launching real ROS nodes.
