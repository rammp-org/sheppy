# Getting started

## Install

One line — installs [uv](https://docs.astral.sh/uv/) if you don't have it,
then puts `sheppy` and `sheppyd` on your `PATH` (`~/.local/bin`) in an
isolated environment:

```bash
curl -LsSf https://rammp-org.github.io/sheppy/install.sh | sh
```

Re-run the same line to upgrade. Pin a branch, tag, or commit with
`SHEPPY_REF=<ref>`; uninstall with `uv tool uninstall sheppy`.

<Callout type="info">
Already have uv? `uv tool install git+https://github.com/rammp-org/sheppy`
does the same thing.
</Callout>

## Run the demo — no ROS required

The repo ships `examples/local-demo.yaml`, a manifest that launches plain
Python processes instead of ROS nodes. It's the fastest way to see sheppy
actually run something, on any machine, with nothing else installed:

```bash
git clone https://github.com/rammp-org/sheppy.git
cd sheppy
sheppy examples/local-demo.yaml
```

The manifest declares two nodes: `clock` (an alternative called `ticker`
that prints the time every second) and `worker` (`steady`, which just sleeps,
and `flaky`, which exits with status 1 after three seconds). That's enough to
walk through everything below.

## The 90-second walkthrough

<Steps>
### Select `clock` → `ticker`

`Enter` opens `clock`'s alternatives, `Enter` again selects `ticker` (its
only one), `Esc` returns focus to the node list. The row's ALTERNATIVE
column now reads `ticker`.

### Launch it — `space`

Within a couple of seconds the row's status glyph turns `●` (green) and the
footer reads `sheppyd ● 1/2 running` — `sheppyd` auto-started on this first
launch.

### Watch it run

Press `3` for the PROCESS tab: `state`, `pid`, a live `uptime`, and a "last
output" tail printing `clock`'s heartbeat, one new line per second.

### Crash it on purpose

Move to `worker` (`↓`), select `flaky` (`Enter`, `↓`, `Enter`, `Esc`), then
`space` to launch it. It runs for about three seconds, then its glyph turns
`✕` (crashed) with a `Δ` — desired (`flaky`) no longer matches actual
(nothing running); see [desired vs actual](/concepts#desired-vs-actual).

### Read its logs

From a second terminal:

```
$ sheppy status
clock                running    ticker         pid=4074426 up 15s
worker               crashed    flaky          pid=4074572 exit=1
```

`flaky` never prints anything before it dies, so `sheppy logs worker` comes
back empty — the exit code, not a log line, is the signal:

```
$ sheppy logs worker
(no output)
```

### Save the selection as a profile — `s`

Type a name (e.g. `demo`), `Enter`. The header now reads `◆ profile demo`,
and `profiles/demo.yaml` appears next to the manifest:

```yaml
selections:
  clock: ticker
  worker: flaky
```

Running the demo from a clone drops that `profiles/` directory into the
checked-out `examples/` folder — expected, not a bug.

### Tear down

Quit the TUI (`Ctrl+C`), then from a shell:

```
$ sheppy down
stopped clock
stopped worker
sheppyd stopped
```
</Steps>

<Callout type="info">
`sheppyd` is the tiny supervisor daemon that actually owns these processes —
quit the TUI and they keep running; reconnect and they're still there. For
architecture, node states, and troubleshooting, see the
[sheppyd guide](/guides/sheppyd).
</Callout>

## Now describe your own system

`local-demo.yaml` is a toy. See [The manifest](/manifest) to write one for
